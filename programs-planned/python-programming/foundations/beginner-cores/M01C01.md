## Introduction
A Python program is code executed by the Python interpreter. Most programs are written in one or more source files (usually with a `.py` extension), which are loaded as modules or as a main script. Upon execution of a source file—via the command `python filename.py`—the interpreter performs the following steps:

1. Reads the source code from the file.
2. Compiles it into bytecode.
3. Executes the bytecode within a newly created module object, which maintains its own global namespace.

The module object and its global namespace persist for the lifetime of the interpreter process (or until removed from `sys.modules`). The interpreter also supports interactive execution in a REPL (Read-Eval-Print Loop), invoked by `python`, where each input block is compiled and executed in a persistent namespace.

At the core of Python's semantics lie two fundamental elements:
- **Objects**: Immutable or mutable entities managed by the runtime, such as integers, strings, lists, functions, or modules.
- **Names**: String identifiers in a namespace that bind to these objects, facilitating reference and access.

Assignment does not "store" a value inside a variable; it establishes or updates a binding between a name and an object. This model underpins critical behaviors like aliasing (multiple names referencing the same object) and mutation (in-place changes to mutable objects), which are essential for debugging and effective programming.

## Core Concepts

### 1. Execution Model: Scripts, Modules, and REPL
Executing a source file creates a dedicated module with its global namespace, where top-level statements—those evaluated in the module’s global namespace during import or script execution, regardless of indentation—are processed sequentially from top to bottom. Statements inside function bodies form the function’s body and run only when the function is called. Control structures (e.g., `if`, `for`, `while`) and function invocations alter the execution path dynamically.

For example, running `python example.py` executes the file's top-level code once in its module namespace. In contrast, importing the module via `import example` executes it once (if not cached) and binds the module object to the name `example` in the importing namespace.

In the REPL, each input block is compiled and executed in an ongoing interactive namespace:
```
>>> x = 10
>>> x + 1
11
```
Here, `x` persists across inputs, bound in the interactive globals.

Comments, prefixed by `#`, are excluded from compilation and execution, aiding documentation without runtime impact.

#### Minimal Script Example
```python
# example.py
print("Starting the program")
calculation = 2 + 3
print("The result is:", calculation)
print("Program complete")
```

**Execution Output**:
```
Starting the program
The result is: 5
Program complete
```

**Key Insights**:
- Statements execute top-to-bottom in the module's global namespace.
- `calculation` binds to the integer object `5` within this namespace.
- Advanced usage (covered later) employs `if __name__ == "__main__":` to differentiate script execution from imports.

### 2. Names, Namespaces, and Assignment
A namespace is a dynamic dictionary-like mapping from names (strings) to objects, such as a module's globals or a function's locals. Assignment is an operation on a namespace or mapping, not on the object itself:

```python
x = 3        # Binds 'x' to the integer object 3 in the current namespace
x = x + 1    # Evaluates to 4 (a new object), then rebinds 'x'
```

Distinctions among assignment forms:
- `x = 1`: Binds or rebinds a name in the namespace; the integer object 1 is unchanged.
- `obj.attr = 1`: Assigns an attribute to an object (for normal user-defined classes, typically recorded in `obj.__dict__`); the object gains or updates the attribute.
- `mapping[key] = 1`: Inserts or updates a key-value pair in a dictionary-like structure; the mapping's contents are modified.

### 3. Identity vs. Equality, Aliasing, and Mutation
Objects may satisfy equality (`a == b`: same value) without sharing identity (`a is b`: same object). The `id()` function yields an object's unique identifier (treated as opaque, though often reflecting memory address in CPython), unique for that object during its lifetime; it can be reused after the object is destroyed.

Aliasing arises when multiple names bind to one object:
```python
x = [1, 2, 3]
y = x          # Aliasing: both bind to the same list
print(x is y)  # True
print(x == y)  # True
print(id(x), id(y))  # Identical values
```

Mutation alters the shared object in place:
```python
y.append(4)    # Mutates the list
print(x)       # [1, 2, 3, 4]
print(y)       # [1, 2, 3, 4]

x = [5, 6]     # Rebinding: 'x' now points to a new list
print(x)       # [5, 6]
print(y)       # [1, 2, 3, 4]
print(x is y)  # False
```

**Key Insights**:
- Mutation propagates across aliases, as it modifies the underlying object.
- Rebinding affects only the targeted name, leaving other aliases intact.

For immutable objects (e.g., integers, strings), "modifications" invariably create new objects and rebind the name:
```python
a = 10
b = a
print(a is b)  # Implementation detail; do not rely on this
a = a + 1      # Creates 11, rebinds 'a'
print(a)       # 11
print(b)       # 10
```

Do not use `is` for value comparison except with singletons (e.g., `None`, `True`, `False`, `Ellipsis`); rely on `==` for general equality checks to avoid relying on implementation details like caching.

## Hands-On Exercises
These activities reinforce execution and binding concepts. Implement in a Python environment, predict outcomes, then verify.

1. **Script vs. REPL Exploration**  
   Create `origin.py`:
   ```python
   # origin.py
   x = 1
   y = x
   print("In script:", x, y)
   ```
   - Execute: `python origin.py`. Observe the output.  
   - Launch REPL (`python`), then:  
     ```python
     >>> import origin
     >>> print(origin.x, origin.y)
     ```  
   **Reflection**: Articulate the namespace for `x` and `y` in the script versus post-import in the REPL. How does the module object mediate access?

2. **Aliasing and Shallow Copying**  
   Predict outputs for:
   ```python
   a = [1, 2]
   b = a
   c = b[:]      # Shallow copy
   b.append(3)
   c.append(4)

   print("a:", a)
   print("b:", b)
   print("c:", c)
   print("a is b:", a is b)
   print("a is c:", a is c)
   print("b is c:", b is c)
   print("a == c:", a == c)
   ```
   **Expected Output** (verify after prediction):
   ```
   a: [1, 2, 3]
   b: [1, 2, 3]
   c: [1, 2, 4]
   a is b: True
   a is c: False
   b is c: False
   a == c: False
   ```
   **Reflection**: Identify flawed assumptions in your predictions regarding mutation's scope or copy semantics.

3. **Names, Attributes, and Items**  
   Execute:
   ```python
   class Box:
       pass

   box = Box()
   box.value = [1]
   mapping = {}
   x = box.value

   mapping["k"] = x
   x.append(2)
   ```
   - Enumerate current-namespace names and their bindings (e.g., via `locals()` or inspection).  
   - Detail `box` attributes (`box.__dict__`).  
   - List `mapping` keys/values.  
   - Employ `id()` to trace aliasing (e.g., `id(box.value)`, `id(mapping["k"])`, `id(x)`).  
   **Expected Insights** (verify after analysis): All three (`box.value`, `mapping["k"]`, `x`) share the mutated list `[1, 2]` with identical `id()` values; `box.__dict__ = {'value': [1, 2]}`; `mapping = {'k': [1, 2]}`.

4. **Nested Aliasing Challenge**  
   Predict and execute:
   ```python
   data = {"a": [1], "b": [1]}
   data["b"] = data["a"]  # Alias the list
   data["a"].append(2)
   print("data:", data)
   print("data['a'] is data['b']:", data['a'] is data['b'])
   print("data['a'] == data['b']:", data['a'] == data['b'])
   ```
   **Expected Output** (verify after prediction):
   ```
   data: {'a': [1, 2], 'b': [1, 2]}
   data['a'] is data['b']: True
   data['a'] == data['b']: True
   ```
   **Reflection**: Trace how the aliasing affects the dictionary's values and why mutation propagates.

## Glossary
- **CPython**: The reference implementation of Python, written in C, which uses a virtual machine to execute bytecode.
- **REPL**: Read-Eval-Print Loop; an interactive environment for executing Python code line by line or in blocks.
- **sys.modules**: A dictionary in the `sys` module that maps module names to their corresponding module objects, used for caching imported modules.
