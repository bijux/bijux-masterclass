## Introduction
Building on the execution model from Core 1, this core introduces mechanisms to alter the linear flow of top-level statements. Python distinguishes between expressions—code fragments that evaluate to objects—and statements, which orchestrate execution but do not yield values. Control structures like conditionals and loops enable decisions and repetition, while short-circuiting in logical operations optimizes evaluation and enables guards. Mastering these allows precise prediction of program behavior, essential for debugging and design.

## Core Concepts

### 1. Expressions vs. Statements
Expressions evaluate to objects and can appear where a value is expected (e.g., in assignments, function arguments, or print statements). Examples include literals (`42`, `"hello"`), arithmetic (`2 + 3`), comparisons (`x > 5`), and function calls (`len(lst)`).

Statements, in contrast, perform actions like assignments (`x = 5`), control flow (`if cond:`), or imports (`import math`) but do not produce values. They cannot be nested inside other expressions; attempting `if x = 5:` raises a syntax error, as assignment is a statement.

**Key Insight**: Interactive REPLs evaluate expressions directly (e.g., `>>> 2 + 3` yields `5`), but scripts execute statements sequentially.

#### Illustrative Example
```python
# expressions.py
result = 2 + 3 * 4  # Expression: evaluates to 14, bound to 'result'
print(result)       # Expression in function call: evaluates to 14
print(len("Python"))  # Expression: evaluates to 6
# if True:  # Statement: controls flow, no value
```

**Execution Output**:
```
14
6
```

### 2. Conditionals: `if`, `elif`, `else`
The `if` statement branches execution based on a condition (an expression evaluating to a truthy or falsy value). Truthy values include non-empty sequences, non-zero numbers, and `True`; falsy include `None`, `0`, empty collections, and `False`. Any object can define its own truthiness via `__bool__` or `__len__`; we rely on the default behaviour here. An optional `else` handles the inverse case; `elif` chains multiple conditions.

Indentation defines the block:
```python
if condition:
    # suite (indented statements)
elif other_condition:
    # another suite
else:
    # final suite
```

Only the first true condition's suite executes; if none, the `else` (if present) runs.

#### Example
```python
# conditionals.py
score = 85
if score >= 90:
    grade = "A"
elif score >= 80:
    grade = "B"
else:
    grade = "C"
print(f"Grade: {grade}")  # Evaluates to "B"
```

**Execution Output**:
```
Grade: B
```

**Key Insight**: Conditions test truthiness, not explicit booleans—e.g., `if lst:` checks non-emptiness.

### 3. Loops: `for` and `while`
Loops repeat suites until a condition fails or an iterable exhausts.

- `for target in iterable:` iterates over elements, binding each to `target`. Suitable for known sequences (lists, ranges).
- `while condition:` repeats while the condition is truthy. Use for unknown iteration counts, but guard against infinite loops.

Both support `break` (exit loop), `continue` (skip to next iteration), and `else` (executes if no `break` occurred).

The `for` loop drives the iterator protocol: it repeatedly calls `iter(iterable)` and `next()` to get each element. If the iterable itself is lazy (e.g., a generator), elements are produced on demand; if it is a list, all elements already exist.

#### Example
```python
# loops.py
# for loop
total = 0
for num in [1, 2, 3]:
    total += num
print(total)  # 6

# while loop
count = 0
while count < 3:
    print(count)
    count += 1
else:
    print("Loop completed without break")  # Executes here

# for-else example
found = False
for item in [1, 2, 3]:
    if item == 4:
        found = True
        break
else:
    print("4 not found")  # Executes, as no break
```

**Execution Output**:
```
6
0
1
2
Loop completed without break
4 not found
```

**Key Insight**: The `while` requires manual condition management; `for-else` and `while-else` run only on natural completion.

### 4. Short-Circuit Evaluation
Logical operators `and`, `or`, and `not` short-circuit: `and` evaluates left-to-right, stopping at the first falsy value (yielding it); `or` stops at the first truthy (yielding it). `not` negates a single operand.

This enables guards: `files and max(files)` avoids `max([])` (raises `ValueError`).

#### Example
```python
# short_circuit.py
files = []  # Empty for first call
print(files and max(files))  # [] (short-circuits on falsy files; returns [] as "default")

files = [1, 3, 2]  # Numeric for clarity
print(files and max(files))  # 3 (truthy files, then max)

# Clearer alternative to short-circuit idiom
def safe_max(items):
    if items:
        return max(items)
    return None  # Explicit default for empty
print(safe_max([]))  # None
```

**Execution Output**:
```
[]
3
None
```

**Key Insight**: Short-circuiting is a behavioral guarantee, not just optimization—use it for guards, but prefer explicit `if` for clarity in most cases. Patterns like `files and max(files)` appear in older code but can be fragile if the "default" value (here, `[]` on empty input) is unexpected; this is why we prefer explicit `if`.

### 5. Tracing Execution Paths
To predict behavior, manually trace: list statements, evaluate conditions sequentially, note branches taken. Use `print` for runtime verification.

For the conditional example with `score = 75`: Path traces to `else` suite, binding `grade = "C"`.

**Key Insight**: Tracing reveals off-nominal paths (e.g., edge cases like `score = None`), fostering robust code.

## Hands-On Exercises
Implement in a Python environment, predict paths/outputs, then verify.

1. **Truthy/Falsy Conditionals**  
   Predict grades for `scores = [95, 80, 70, 0, None]` using:
   ```python
   # grade.py
   def get_grade(score):
       if score is None or score < 0:
           return "Invalid"
       elif score >= 90:
           return "A"
       elif score >= 80:
           return "B"
       else:
           return "C"
   for s in scores:
       print(f"{s}: {get_grade(s)}")
   ```
   **Expected Output** (verify after prediction):
   ```
   95: A
   80: B
   70: C
   0: C
   None: Invalid
   ```
   **Reflection**: Why does `0` yield "C" not "Invalid"? Trace the `is None` short-circuit.

2. **Loop with Controls**  
   Predict output of:
   ```python
   # loop_control.py
   nums = [1, 2, 3, 4, 5]
   total = 0
   for n in nums:
       if n % 2 == 0:
           continue
       total += n
       if total > 4:
           break
   else:
       print("No early exit")
   print(total)
   ```
   **Expected Output**:
   ```
   9
   ```
   **Reflection**: Trace additions (1→1, 3→4, 5→9 with break); explain why `else` skips.

3. **Short-Circuit Guard**  
   Implement and predict:
   ```python
   # guard.py
   def safe_max(items):
       if items:
           return max(items)
       return None  # Matches main text
   print(safe_max([]))  # Predict
   print(safe_max([3, 1, 4]))
   ```
   **Expected Output**:
   ```
   None
   4
   ```
   **Reflection**: Rewrite using short-circuit (`items and max(items)`); discuss differences in behavior for empty lists (returns `[]` vs `None`) and why explicit `if` is preferable.

4. **Trace a Combined Flow**  
   Write and trace a script summing even numbers up to `n=10`, skipping multiples of 3, stopping if sum exceeds 20:
   ```python
   # trace.py
   n = 10
   total = 0
   i = 0
   while i <= n:
       i += 1
       if i % 2 != 0 or i % 3 == 0:
           continue
       total += i
       if total > 20:
           break
   print(total)
   ```
   **Expected Output**: `24` (breaks after adding 10; trace steps manually).

## Glossary
- **Truthy/Falsy**: Values treated as true/false in conditions; e.g., non-empty collections are truthy, `None` is falsy.
- **Iterable**: An object yielding elements via `__iter__` or `__getitem__`, consumable by `for` loops (e.g., lists, ranges).
