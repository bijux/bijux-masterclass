- Explain mutability across data types: contrast in-place modifications in mutable collections with the immutability of scalars and sequences.

## Introduction
Building on expressions and control flow from Core 2, this core establishes Python's foundational data types: scalars for atomic values and collections for grouped data. Scalars (int, float, bool, None) and immutable sequences (str, tuple) resist modification, while mutable collections (list, dict, set) enable in-place changes but introduce aliasing hazards. Transformations create new objects to ensure safety. This classification underpins predictable code, with informal notes on performance seeding later algorithmic discussions. Other core types, such as range (lazy integer sequences for loops) and binary types like bytes/bytearray (for raw data), exist but are covered later.

| Type          | Literal Example | Mutable? | Indexed? | Allows `in`? | Typical Use                  |
|---------------|-----------------|----------|----------|--------------|------------------------------|
| int           | `42`            | No       | No       | N/A          | Exact counts, IDs            |
| float         | `3.14`          | No       | No       | N/A          | Measurements, approximations |

### 1. Basic Scalar Types
Scalars hold single values: numbers (int, float), boolean (bool), and null (None, a singleton instance of NoneType). They are immutable, so aliasing poses no mutation risk—operations yield new objects. Truthiness (from Core 2) applies: non-zero numbers, and non-empty sequences/collections are truthy; 0, None, False, and empty strings/collections (e.g., "", [], {}) are falsy.

#### Core Operations for Scalars
| Type    | Operation       | Syntax                  | Mutates? | Returns          | Notes |
|---------|-----------------|-------------------------|----------|------------------|-------|
| int    | Construction   | `42`, `int("10")`      | N/A     | New int         | Arbitrary precision; no overflow. |
| int    | Arithmetic     | `+ - * / // % **`      | No      | New int/float   | `//` floor division; `**` exponent. |
| int    | Comparison     | `< > == <= >= !=`      | No      | bool            | Exact equality. |
| float  | Construction   | `3.14`, `float("1.5")` | N/A     | New float       | IEEE 754 binary; inexact (e.g., 0.1 + 0.2 != 0.3). |
| float  | Arithmetic     | `+ - * /`              | No      | New float       | Rounding errors common. |
| float  | Comparison     | `< > ==` etc.          | No      | bool            | Avoid `==` for precision; use tolerances later. |
| bool   | Construction   | `True`, `False`, `bool(x)` | N/A  | bool            | Subtype of int (`True == 1`); do not rely on numeric use. |
| bool   | Logical        | `not b`, `b1 and b2`   | No      | bool            | Short-circuits as in Core 2. |
| None   | Construction   | `None`                 | N/A     | None            | Singleton for "no value"; falsy. |
| None   | Comparison     | `x is None`            | No      | bool            | Use `is`, not `==`. |

#### Example
```python
# scalars.py
x = 10 // 3  # 3
y = 0.1 + 0.2  # Approx. 0.3
print(f"{x} {y == 0.3}")  # 3 False
print(bool(""))  # False
print(None is None)  # True
```

**Execution Output**:
```
3 False
False
True
```

**Key Insight**: Scalars are immutable; arithmetic/comparisons produce new values. Complex numbers exist but are covered later.

### 2. Immutable Sequences: Strings and Tuples
Strings (`str`) are immutable sequences of Unicode characters; tuples provide fixed-size, ordered, immutable sequences of arbitrary objects. Both support indexing, slicing, and membership but no in-place mutation. Unpacking is a common tuple idiom: `a, b = (1, 2)` binds sequentially. `len()` works on both, yielding expected O(1) length.

#### Core Operations for Strings and Tuples
| Type    | Operation       | Syntax                  | Mutates? | Returns          | Notes |
|---------|-----------------|-------------------------|----------|------------------|-------|
| str    | Construction   | `"hello"`, `str(42)`   | N/A     | New str         | Unicode text; empty `""`. |
| str    | Access         | `s[i]`, `s[start:end]` | No      | char or new str | IndexError; slicing shallow copy. |
| str    | Membership     | `c in s`               | No      | bool            | Expected O(n) scan. |
| str    | Iteration      | `for c in s`           | No      | N/A             | Unpacks characters. |
| str    | Non-mutating   | `s.upper()`, `s.lower()`, `s.split(sep)`, `sep.join(iter_of_strs)`, `s + other` | No | New str or list | `split()` yields list; `+` concatenation expected O(n). |
| tuple  | Construction   | `(1, 2)`, `tuple(iterable)` | N/A  | New tuple       | Singletons `(x,)`; empty `()`. |
| tuple  | Access         | `t[i]`, `t[start:end]` | No      | Element or new tuple | IndexError. |
| tuple  | Membership     | `x in t`               | No      | bool            | Expected O(n) scan. |
| tuple  | Iteration      | `for x in t`           | No      | N/A             | Unpacking: `a, b, *rest = t`. |
| tuple  | Non-mutating   | `t + other`, `t.count(x)` | No | New tuple or int | No mutation methods. |

#### Example
```python
# immutables.py
t = (1, "two", 3)
print(t[1])  # "two"
print(t + (4,))  # (1, "two", 3, 4) (new tuple)
a, b = t[:2]  # Unpacking
print(a, b)  # 1 two

s = "hello"
print(s.split("l"))  # ['he', '', 'o']
print(s[::-1])  # "olleh" (reversed slice)
```

**Execution Output**:
```
two
(1, 'two', 3, 4)
1 two
['he', '', 'o']
olleh
```

**Key Insight**: Immutable sequences enable safe aliasing; slicing/unpacking create or extract without change.

### 3. Mutable Collections: Lists, Dictionaries, and Sets
Lists offer ordered, mutable sequences; dictionaries map hashable keys to values; sets store unique, unordered elements. All support `in` membership and `len()` (expected O(1)); mutating during iteration can lead to skipped elements or runtime errors (e.g., RuntimeError for dicts); avoid it unless you know exactly what you’re doing. Keys/elements must be hashable: built-in immutables like int, str, and tuples of hashables are fine; mutable types like list, dict, set cannot be used as keys or set elements.

#### Core Operations for Lists
| Operation       | Syntax                  | Mutates? | Returns          | Notes |
|-----------------|-------------------------|----------|------------------|-------|
| Construction   | `[1, 2]`, `list(iterable)` | N/A   | New list        | Comprehensions for transformations. |
| Access         | `lst[i]`, `lst[start:end]` | No    | Element or new list | IndexError; slicing shallow copy. |
| Membership     | `x in lst`             | No      | bool            | Expected O(n) scan. |
| Iteration      | `for x in lst`         | No      | N/A             | Supports `enumerate`. |
| Mutation       | `lst.append(x)`, `lst.extend(iter)`, `lst.pop(i)`, `lst.insert(i, x)`, `lst.remove(x)`, `lst.sort(key=None)`, `lst.reverse()`, `lst.clear()` | Yes | None or element | `append` expected O(1) amortized; `sort` expected O(n log n), returns None. |
| Non-mutating   | `lst + other`, `lst * n`, `sorted(lst, key=None)` | No  | New list        | Concatenation expected O(n); `sorted` stable. |
| Copy           | `lst[:]`, `lst.copy()` | No      | New list        | Shallow. |

#### Core Operations for Dictionaries
| Operation       | Syntax                  | Mutates? | Returns          | Notes |
|-----------------|-------------------------|----------|------------------|-------|
| Construction   | `{"a": 1}`, `dict(pairs)` | N/A   | New dict        | Comprehensions supported. |
| Access         | `d[key]`, `d.get(key, default)` | No  | Value           | `KeyError`; `get` safe. |
| Membership     | `key in d`             | No      | bool            | Keys only; expected O(1) average. |
| Iteration      | `for k in d` (keys)    | No      | N/A             | `items()` for pairs; insertion order (3.7+). |
| Mutation       | `d[key] = value`, `d.update(other)`, `d.pop(key)`, `d.popitem()`, `d.clear()` | Yes | None or value   | Expected O(1) average. |
| Non-mutating   | `d \| other` (3.9+); pre-3.9: `{**d, **other}` or (merged = d.copy(); merged.update(other)), comprehensions | No | New dict        | Union merges. |
| Copy           | `d.copy()`             | No      | New dict        | Shallow. |

#### Core Operations for Sets
| Operation       | Syntax                  | Mutates? | Returns          | Notes |
|-----------------|-------------------------|----------|------------------|-------|
| Construction   | `{1, 2}`, `set(iterable)` | N/A   | New set         | `{}` is dict; use `set()`. |
| Access         | No direct; use `in`    | No      | N/A             | Membership primary. |
| Membership     | `x in s`               | No      | bool            | Expected O(1) average. |
| Iteration      | `for x in s`           | No      | N/A             | Arbitrary order. |
| Mutation       | `s.add(x)`, `s.update(iter)`, `s.remove(x)`, `s.discard(x)`, `s.clear()` | Yes | None            | Duplicates ignored. |
| Non-mutating   | `s \| other`, `s & other`, `s - other`, `s ^ other`, `s <= other` (subset) | No | New set or bool | Union, intersection, etc. |
| Copy           | `s.copy()`             | No      | New set         | Shallow. |

#### Examples
```python
# mutables.py
fruits = ["apple", "banana"]
fruits.append("cherry")
print(fruits)  # ['apple', 'banana', 'cherry']

person = {"name": "Alice"}
person["age"] = 30
print(person["name"])  # Alice

evens = {2, 4}
evens.add(6)
print(evens)  # {2, 4, 6}
```

**Execution Output**:
```
['apple', 'banana', 'cherry']
Alice
{2, 4, 6}
```

**Key Insight**: Mutable operations are expected O(1) average for dict/set; lists vary by position.

### 4. Mutability and Aliasing
Scalars (int, float, bool, None) and immutable sequences (str, tuple) are immutable: aliasing is harmless, as "changes" rebind names to new objects. Mutable collections (list, dict, set) alter in place, propagating via aliases. A tuple's structure (which objects it refers to) is immutable, but the objects it refers to may themselves be mutable and can change.

#### Example
```python
# mutability.py
lst1 = [1, [2, 3]]  # Mutable
s1 = "immutable"  # Immutable str
lst2 = lst1  # Alias
s2 = s1
lst2.append(4)
print(lst1)  # [1, [2, 3], 4]
print(s1)  # "immutable" (unchanged)

lst3 = lst1[:]  # Shallow copy
lst3[0] = 5
print(lst1)  # [1, [2, 3], 4]
print(lst1[1] is lst3[1])  # True (nested shared)
```

**Execution Output**:
```
[1, [2, 3], 4]
immutable
[1, [2, 3], 4]
True
```

**Key Insight**: Immutables + aliasing safe; mutables require copies to isolate changes.

### 5. Safe Basic Transformations
Comprehensions create new collections, leaving originals unchanged—unlike mutating methods. `map()`/`filter()` return lazy iterators; materialize with `list()` or `set()`. Avoid mutating during iteration to prevent errors, e.g., `for x in nums: nums.append(x * 2)` (infinite loop risk).

#### Example
```python
# transformations.py
nums = [1, 2, 3, 4, 5]
evens = [n for n in nums if n % 2 == 0]  # New list
print(evens)  # [2, 4]

squared = {n: n**2 for n in nums}  # New dict
print(squared)  # {1: 1, 2: 4, 3: 9, 4: 16, 5: 25}

evens_set = set(filter(lambda n: n % 2 == 0, nums))  # New set from iterator
print(evens_set)  # {2, 4}
```

**Execution Output**:
```
[2, 4]
{1: 1, 2: 4, 3: 9, 4: 16, 5: 25}
{2, 4}
```

**Key Insight**: Transformations yield new objects, preserving originals.

## Glossary
- **Mutable**: Objects modifiable in place (e.g., lists, dicts, sets).  
- **Immutable**: Unchangeable after creation (e.g., int, str, tuples).  
- **Shallow Copy**: Duplicates outer structure but shares nested objects (e.g., `lst[:]`).  
- **Hashable**: Types with stable `__hash__`/`__eq__` (e.g., for dict keys).
