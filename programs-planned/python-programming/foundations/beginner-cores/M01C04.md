## Introduction
Extending data handling from Core 3, functions encapsulate logic for reuse, abstraction, and modularity. Defined with `def`, they introduce local namespaces for parameters and variables, distinct from the global scope. Parameters formalize inputs, while arguments supply values—positional by order, keyword by name. Scope rules (LEGB) ensure controlled name access, preventing pollution. Pure functions—those depending solely on inputs and producing consistent outputs—promote reliable, testable code. This foundation enables structured programs, with performance notes on call overhead seeding later discussions.

## Core Concepts

### 1. Defining and Calling Functions
Functions are defined with `def name(parameters):`, followed by an indented suite and optional `return` (yields a value; omission returns `None`). Calls execute the suite, binding arguments to parameters.

Docstrings (triple-quoted strings post-`def`) document behavior.

#### Example
```python
# functions.py
def greet(name):  # Parameter 'name'
    """Greet a person by name."""
    return f"Hello, {name}!"

message = greet("Alice")  # Argument "Alice"
print(message)  # Hello, Alice!
```

**Execution Output**:
```
Hello, Alice!
```

**Key Insight**: Calls create a new local namespace; `return` ends execution and yields a value.

### 2. Parameters vs. Arguments
Parameters are placeholders in definitions; arguments are values in calls. Positional arguments match order; keyword arguments specify by name (e.g., `greet(name="Bob")`), allowing reordering and defaults (e.g., `def greet(name="World"):`).

Variable arguments: `*args` packs extras as tuple (positional), `**kwargs` as dict (keyword). Use sparingly for flexibility.

#### Parameter and Argument Types
| Type              | Definition Syntax              | Call Syntax                  | Notes |
|-------------------|--------------------------------|------------------------------|-------|
| Positional        | `def f(a, b):`                | `f(1, 2)`                   | Order matters; required. |
| Keyword           | `def f(a, *, b):` (after *)   | `f(a=1, b=2)`               | Named; keyword-only after `*`. |
| Default           | `def f(a, b=2):`              | `f(1)` or `f(1, 3)`         | Optional; must follow non-defaults. |
| Variable Positional | `def f(*args):`              | `f(1, 2, 3)`                | Packs as tuple; after fixed params. |
| Variable Keyword  | `def f(**kwargs):`            | `f(x=1, y=2)`               | Packs as dict; last. |

#### Example
```python
# params.py
def add(x, y=0, *extras, z=10):  # Defaults, *extras
    total = x + y + z + sum(extras)
    return total

print(add(1))  # 11 (y=0, z=10, extras=())
print(add(1, 2, 3, z=4))  # 10 (x=1, y=2, extras=(3,), z=4)
```

**Execution Output**:
```
11
10
```

**Key Insight**: Defaults evaluated once at definition; `*args`/`**kwargs` enable variadic calls but obscure signatures.

### 3. Scope and Name Resolution
Python resolves names via LEGB: Local (function body), Enclosing (nested functions), Global (module), Built-in (e.g., `len`). Assignments create locals; `global`/`nonlocal` override for outer scopes.

Nested functions access enclosing via `nonlocal`; avoid globals for purity.

#### Scope Resolution (LEGB)
| Scope     | Resolution Order | Example Access                  | Notes |
|-----------|------------------|---------------------------------|-------|
| Local     | First            | Variable in function body       | Created by assignment. |
| Enclosing | Second           | Outer function var in inner     | Use `nonlocal` to modify. |
| Global    | Third            | Module-level var                | Use `global` to modify. |
| Built-in  | Last             | `print`, `len`                  | Shadowable but avoid. |

#### Example
```python
# scope.py
count = 0  # Global

def outer():
    count = 1  # Enclosing local
    def inner():
        nonlocal count  # References enclosing
        count += 1
        print(count)  # 2
    inner()

outer()
print(count)  # 0 (global unchanged)
```

**Execution Output**:
```
2
0
```

**Key Insight**: LEGB prevents unintended global changes; `nonlocal` enables enclosing modifications.

### 4. Basic Pure-Style Design
Pure functions: deterministic (same inputs → same outputs), side-effect-free (no prints, mutations, I/O), and composable. Favor parameters/returns over globals/mutations; testability follows.

Contrast impure: e.g., functions modifying globals or printing.

#### Pure vs. Impure Design
| Aspect             | Pure Example                  | Impure Example                | Why Pure? |
|--------------------|-------------------------------|-------------------------------|-----------|
| Determinism       | `def square(x): return x**2` | `def square(x): print(x); return x**2` | Predictable outputs. |
| Side Effects      | `def add(a, b): return a + b` | `def add(a, b): global total; total += a + b` | No hidden state changes. |
| Composability     | `map(square, [1,2])`         | Relies on external mutation   | Reusable in pipelines. |

#### Example
```python
# pure.py
def pure_max(a, b):
    return a if a > b else b  # Pure: inputs → output

def impure_max(a, b):
    print(f"Comparing {a}, {b}")  # Side effect
    return a if a > b else b

print(pure_max(3, 1))  # 3 (no print)
```

**Execution Output**:
```
3
```

**Key Insight**: Purity aids debugging and reuse; enforce via local scope and returns.

### 5. Tracing Function Calls
Trace calls by noting argument binding, suite execution, and returns. Use for prediction, especially with scopes/nesting.

For `outer()` above: Global `count=0` unchanged; enclosing `count=1` incremented to 2 via `nonlocal`.

**Key Insight**: Tracing reveals scope interactions, preventing name errors.

   def multiply(a, b=2, *extras):
       return a * b * (1 + sum(extras))

   print(multiply(3))  # 6 (b=2, extras=())
   print(multiply(3, 4, 1, z=5))  # Error? No, z ignored
   ```
   **Expected Output**:
   ```

   **Expected Output**:
   ```
   6
   24
   ```
   **Reflection**: Why z ignored? Add **kwargs to capture.

2. **Scope Resolution**  
   Predict:
   ```python
   # scope_ex.py
   x = "global"
   def outer():
       x = "enclosing"
       def inner():
           x = "local"
           print(x)  # local
       inner()
       print(x)  # enclosing

   outer()
   print(x)  # global
   ```
   **Expected Output**:
   ```
   local
   enclosing
   global
   ```
   **Reflection**: Trace LEGB for each print.

3. **Pure Design**  
   Rewrite impure `total = 0; def impure_add(n): global total; total += n` as pure:
   ```python
   # pure_ex.py
   def pure_add(current_total, n):
       return current_total + n

   total = pure_add(total, 5)  # Use explicitly
   print(total)  # Assuming initial 0 +5 =5
   ```
   **Expected Output** (with initial 0):
   ```
   5
   ```
   **Reflection**: Why pure better for testing?

4. **Variable Arguments**  
   Define `sum_all(*numbers, scale=1): return sum(numbers) * scale`:
   ```python

   ```
   **Expected Output**:
   ```
   6
   30
   ```
   **Reflection**: Role of defaults with *args?

## Glossary
- **Parameter**: Formal variable in function definition.  
- **Argument**: Actual value passed to function.  
- **Scope (LEGB)**: Local, Enclosing, Global, Built-in name resolution order.  
- **Pure Function**: Deterministic, side-effect-free, input-output focused.
