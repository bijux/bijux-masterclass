# Ten-day study plan

Each numbered module is one intensive day. The course is designed for approximately eight to ten focused hours per day, with breaks. The schedule is demanding because every day combines specification, design, implementation, adversarial testing, and evidence review.

| Time | Work |
|---|---|
| 08:30–09:00 | Retrieval review and predecessor repair |
| 09:00–11:00 | Read the authoritative chapter and reproduce its examples |
| 11:15–12:30 | Answer exercises without the key |
| 13:30–15:00 | Compare answers and revise reasoning |
| 15:15–18:00 | Run the controlled laboratory |
| 19:00–20:00 | Review Python/TypeScript parity and evidence |
| 20:00–21:00 | Complete checkpoint and write the engineering decision |

The weekend after Day 5 is for repair and consolidation, not new modules. Re-run Modules 1–5 from a clean checkout, revisit every weak answer, and ensure the graph layer has not bypassed the service boundaries.

A module is complete only when its checkpoint passes. Reading ahead while a checkpoint is red hides misconceptions that later modules amplify.
