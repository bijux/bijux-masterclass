# Reliability Case

The course’s claims are organized as six critical journeys, twelve failure modes, thirty active REL requirements, proof mapping, SLO/alert catalogs, dependency policies, and residual risks.

## Machine-readable sources

- `capstone/reliability-case/journeys.yaml`
- `failure-modes.yaml`
- `requirements.yaml`
- `proof-map.yaml`
- `slo-catalog.yaml`
- `alert-catalog.yaml`
- `dependency-policies.yaml`
- `residual-risks.yaml`

## Argument

A requirement is active only when it has a journey/failure source and evidence route. The course core proof rejects orphaned requirements, missing proof paths, invalid alert/runbook links, and contradictory release claims.

## Authority

The reliability case is course policy. W3C, IETF, OpenTelemetry, Prometheus/OpenMetrics, Kubernetes, and SRE sources inform specific mechanisms but do not choose the organization’s business objective for it.
