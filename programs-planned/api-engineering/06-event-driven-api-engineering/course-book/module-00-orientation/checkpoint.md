# Orientation Checkpoint — Event-Driven API Engineering

## Required result

- a clean predecessor or starting boundary;
- a recorded primary and comparison track;
- a readable orientation evidence directory;
- one proof-sensitivity demonstration;
- a clean dependency-light course proof.

## Demonstrate

Without reading the chapter, explain:

- why Course 6 follows Course 5;
- which earlier guarantees must not be weakened;
- which new responsibility this course owns;
- which artifact is authoritative for learning and which artifact is authoritative for system state or contract;
- which current claim requires live infrastructure.

## Commands

```bash
make doctor
make predecessor-proof
make core-proof
make capstone-tour
```

## Defend the design

Show the planted defect and the first failing oracle. Explain why a different proof would have been too high-level or too weak. Then show the comparison-track location for the same invariant without demanding identical source structure.

## Continue only when

The predecessor is intact, all dependency-light commands pass, the evidence boundary is honest, and you can state the course's incoming and outgoing responsibilities in one coherent paragraph.
