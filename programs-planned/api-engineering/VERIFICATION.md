# Verification Boundary

This program distinguishes a **published teaching claim** from an **executed proof in the current environment**. A green dependency-light route establishes only the mechanisms it actually runs. It never converts a missing database, broker, external validator, documentation tool, or representative workload into a synthetic pass.

## Program-wide release gates

The release route verifies:

- six ordered courses and sixty numbered modules;
- one continuous Analysis Runs Platform story;
- 354 course-book pages plus ten program-book pages;
- 480 exercise prompts with matching worked answers;
- sixty failure-oriented labs and sixty evidence checkpoints;
- complete combined documentation navigation;
- five byte-identical adjacent-course handoffs;
- learner-facing links, chapter depth, answer completeness, and repeated-prose guards;
- Python and JavaScript syntax;
- duplicate-key-aware JSON, YAML, and TOML parsing;
- exact course and program manifests;
- every course's dependency-light executable proof.

## Course-local evidence

Each course keeps its strongest environment-backed routes separate from its dependency-light core:

1. **OpenAPI Contract Engineering** proves document structure, references, schema fixtures, provider ownership, workflows, audience views, and compatibility rules. Independent external OpenAPI tools remain a separate route.
2. **Contract-Driven API Service Engineering** proves domain, storage, artifact, webhook, migration, and cross-language mechanisms locally. Real PostgreSQL concurrency, locking, recovery, and coexistence require a live database.
3. **API Security Engineering** proves threat traceability, policy decisions, hostile vectors, token and webhook profiles, incident logic, and release rules. An operated identity system and production key infrastructure are outside the local fixture authority.
4. **API Reliability and Observability Engineering** proves deadline, retry, lifecycle, telemetry, SLO, alert, runbook, reconciliation, and fault-model logic. A live telemetry topology and controlled game day remain environment-backed.
5. **API Performance, Capacity, and Traffic Engineering** proves workload identity, statistics, admission, cache, traffic, plan-analysis, capacity, and release arithmetic. Local timing is mechanism evidence, not production capacity evidence.
6. **Event-Driven API Engineering** proves event identity, delivery attempts, acknowledgement, outbox/inbox effects, replay, stream-time policy, security, dead-letter custody, and compatibility. Live broker and PostgreSQL behavior remain separate.

## Publication rule

A result is described as **passed** only when the corresponding command was executed successfully. A route that could not run is described as **not executed**, together with the missing dependency and the lower evidence classes that did pass. This is an intentional part of the curriculum: honest evidence boundaries are an engineering skill, not release-note decoration.
