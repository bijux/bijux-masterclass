# Production claims and evidence boundary

The dependency-light core is a complete instructional implementation of platform
semantics. It is not represented as a hosted enterprise developer portal, a
production registry, or an operated Backstage installation.

## Executed locally

- exact predecessor and contract-artifact digests;
- catalog identity, ownership, relation, and orphan checks;
- immutable registry release behavior;
- policy, exception, scorecard, lifecycle, and retirement decisions;
- deterministic template rendering;
- static portal generation and search;
- sandbox isolation and expiry semantics;
- SDK metadata, SBOM, and provenance-profile integrity;
- gateway desired-state drift checks;
- product analytics and consumer-impact calculations;
- Python and TypeScript semantic parity;
- network-laboratory behavior;
- accepted and rejected platform release decisions.

## Environment-backed

A real Backstage deployment, external schema registries, package registries,
hosted identity, signed attestations from a hardened build platform, strict
MkDocs rendering, and cloud gateway integration require external environments.
Their integration points and expected evidence are documented but are never
converted into synthetic passes.
