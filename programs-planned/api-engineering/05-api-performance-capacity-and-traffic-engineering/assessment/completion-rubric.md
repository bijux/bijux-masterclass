# Completion rubric

The learner completes Course 5 only when all statements are evidenced:

1. A result cannot be compared when workload or environment identity differs.
2. Offered, started, admitted, completed, rejected, failed, and missing
   populations reconcile.
3. Correctness, security, and reliability checks precede performance metrics.
4. At least three comparable baseline runs establish a noise band.
5. HTTP optimization preserves validators, ranges, bytes, and authorization.
6. A PostgreSQL decision includes the exact query, parameters, representative
   data, plan, buffer evidence, write cost, and migration risk.
7. Runtime work identifies a measured hotspot and demonstrates a mechanism.
8. Admission control places an explicit bound on active and waiting work.
9. Cache keys include every identity that changes authorization or bytes.
10. Traffic policy provides tenant fairness and truthful overload outcomes.
11. Capacity models state uncertainty, headroom, cost, and first bottleneck.
12. The release gate can return accepted, rejected, or inconclusive.
13. All ten planted defects are rejected by named oracles.
14. One primary language track and the comparative track agree on shared
    vectors and release decisions.
15. `make core-proof` and `make manifest-proof` pass from a clean checkout.
