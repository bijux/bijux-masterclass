# Final performance review

The final exercise gives the learner a fixed API 1.2 system, six workload
envelopes, plan fixtures, runtime profiles, queue measurements, cache evidence,
and capacity assumptions. The review must identify one limiting resource,
select one candidate change, reject at least one attractive but invalid change,
and issue an `accepted`, `rejected`, or `inconclusive` release decision.

A defensible review includes:

1. workload and environment identity;
2. inherited correctness, security, and reliability oracles;
3. baseline variability;
4. bottleneck hypothesis and predicted mechanism;
5. before/after evidence;
6. side effects and cost;
7. rollback conditions;
8. baseline lineage;
9. residual risk;
10. sanitized handoff material for Course 6.
