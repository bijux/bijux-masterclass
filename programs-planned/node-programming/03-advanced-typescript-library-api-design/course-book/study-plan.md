# Ten-Day Study Plan

This is a dense course. Each day is one complete module.

| Time | Work |
|---|---|
| 08:30–09:00 | Reconstruct the previous day without notes |
| 09:00–11:15 | Read the chapter and trace every type relationship by hand |
| 11:30–12:30 | Predict eight investigations before running them |
| 13:30–15:00 | Diagnose and repair the workbook cases |
| 15:15–17:15 | Build the independent laboratory |
| 17:30–19:00 | Transfer the mechanism into SchemaKit |
| 19:30–20:15 | Inspect emitted declarations and add adversarial evidence |
| 20:15–20:30 | Write five retrieval prompts for the next morning |

## Day 1 — Module 21

Create an assignability ledger. For each assignment, name source, target, required members, optionality, readonly capability, freshness, widening, and any assertion. Complete Structural Contract Catalog and define SchemaKit’s public result and issue shapes.

## Day 2 — Module 22

Name the relationship represented by each generic parameter. Trace inference sites and use `keyof`/indexed access without losing literal information. Complete Typed Projection Engine and establish `Schema<T>` plus `Infer<S>`.

## Day 3 — Module 23

Evaluate conditional types one union member at a time. Mark where distribution occurs and how it is disabled. Complete Command Outcome Matrix and derive SchemaKit output types without duplicating them.

## Day 4 — Module 24

Write mapped transformations as a key table before writing syntax. Estimate template-literal cross products. Complete Typed Change Event Surface and derive object-schema required and optional fields.

## Day 5 — Module 25

Draw producer and consumer arrows for every generic occurrence. Compare methods with function properties. Complete Variance-Safe Event Router and review SchemaKit’s covariance and callback boundaries.

## Day 6 — Module 26

Build and inspect declarations before reading implementation source. Complete Legacy Runtime Declaration Facade and add declaration/type tests to SchemaKit.

## Day 7 — Module 27

Trace one consumer import through package metadata, TypeScript resolution, emitted JavaScript, Node resolution, and declaration lookup. Complete Encapsulated ESM Library Surface and publish SchemaKit’s three supported subpaths.

## Day 8 — Module 28

Trace one unknown value through schema, path context, result, and inferred output. Complete Composable Decoder Library and finish SchemaKit’s runtime combinators.

## Day 9 — Module 29

Review each proposed change across seven compatibility surfaces. Complete Evolvable Client SDK and add SchemaKit compatibility fixtures, deprecations, and migration policy.

## Day 10 — Module 30

Perform the complete library audit, run every package and investigation, inspect the declarations and packed surface, then implement the independent discriminated-union extension from a change-impact map.
