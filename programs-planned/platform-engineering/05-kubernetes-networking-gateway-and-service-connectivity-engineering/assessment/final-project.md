# Final project — Atlas Connectivity Plane 1.0

The final project is a release defense, not a manifest submission.

## Required deliverables

Submit:

1. the accepted Atlas Connectivity Plane release candidate;
2. all ten checkpoint dossiers;
3. a packet-path ledger for one public, one internal, one egress, and one stale-data-plane flow;
4. the final game-day report;
5. the Gateway API implementation and conformance profile;
6. the CNI, Service, DNS, NetworkPolicy, TLS, and egress evidence inventory;
7. a list of every environment-backed claim that remains not executed;
8. the exact Course 6 handoff and its manifest proof.

## Live defense

The reviewer may change one route, endpoint condition, DNS answer, policy selector, listener hostname, certificate, address family, redirect, or locality assumption. Before running a command, identify:

- the earliest transition the change should affect;
- the component that owns that transition;
- one positive observation;
- one negative control;
- the repair with the smallest justified authority.

## Passing standard

A score of 85/100 is required, subject to the non-compensable failures in the course-book final defense. A technically functional result does not pass if it disables TLS verification, authorizes by unstable IP identity, uses an allow-all final policy, hides missing outcomes, weakens the Course 4 workload contract, or presents local evidence as production proof.
