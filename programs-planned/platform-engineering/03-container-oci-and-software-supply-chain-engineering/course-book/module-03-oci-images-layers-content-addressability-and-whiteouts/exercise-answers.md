# Worked answers — OCI images and content addressability

These are worked engineering arguments, not slogans. Compare the conclusion, the mechanism that supports it, the counterexample it excludes, and the evidence that would make the decision reviewable.
## 1. Why must a descriptor verify media type, digest, and size rather than digest alone?

The digest proves the exact bytes, size catches truncation and transfer mismatches early, and media type supplies the schema/semantics used to parse the bytes. Digest alone cannot tell whether the bytes should be interpreted as a manifest, config, layer, or arbitrary artifact. A verifier should check all descriptor constraints before parsing.

## 2. A layer is recompressed with a different gzip timestamp. Predict the blob digest and DiffID changes.

The compressed blob bytes change, so the distribution digest and usually the compressed size change. After decompression, the tar stream is identical, so the DiffID remains the same. If tar metadata also changes, both identities may change. This is why the configuration stores DiffIDs while the manifest stores compressed blob descriptors.

## 3. Explain why the image configuration digest changes when only `Env` changes.

The configuration object is serialized and content-addressed. Changing `Env` changes its JSON bytes and therefore its digest. The manifest embeds the new config descriptor, so the manifest bytes and manifest digest also change. Layers can remain unchanged. The release identity still changes because runtime behavior changed.

## 4. Apply this sequence: Layer A creates `/app/a` and `/app/b`; Layer B adds `/app/.wh.a`; Layer C marks `/app` opaque and adds `/app/c`. What remains?

After A: `a` and `b` exist. B whiteouts `a`, leaving `b`. C’s opaque marker hides all lower-layer children of `/app`, including `b`, then adds `c`. The final directory contains only `/app/c` (plus any same-layer entries). The whiteout marker itself is not a normal final file.

## 5. Why can final-rootfs scanning miss a leaked credential?

A later layer can delete or overwrite a path while the earlier immutable layer remains in the image graph. Registry readers can fetch and unpack that blob directly. Scanning only the merged filesystem sees the current view, not historical bytes. Secret review must inspect layers and prevent secrets entering the build context/history.

## 6. Distinguish an image manifest from an image index.

A platform-specific image manifest identifies one configuration and ordered layer set, generally for one OS/architecture. An image index is a higher-level list of descriptors, commonly selecting among platform-specific manifests. Index identity represents the multi-platform release set; manifest identity represents one selected image variant.

## 7. A manifest descriptor says `linux/arm64`, but the executable ELF header is x86-64. Which stage should reject it?

The publisher’s release validation should reject it before registry promotion. The registry may store structurally valid bytes and the client may select by the false label. Runtime execution will fail too late. Course policy independently inspects executable architecture and requires it to match the descriptor.

## 8. List five tar metadata fields that can break reproducible layer digests.

Modification time, path order, numeric UID, numeric GID, owner/group names, modes, pax headers, xattrs, link representation, and gzip headers can all change bytes. A reproducible builder normalizes the fields it controls and records the remaining environment/toolchain assumptions.

## 9. Why is `history.created_by` not trustworthy build provenance?

The image author controls descriptive history strings. They may be incomplete, rewritten, or generated by a frontend without proving which source, builder identity, dependencies, or parameters produced the object. Provenance requires a separately verifiable statement bound to the subject digest and an authenticated builder identity.

## 10. An SBOM artifact refers to yesterday’s image digest while today’s tag has moved. Should promotion pass?

Promotion fails. The SBOM may be valid for yesterday’s digest, but it says nothing about the bytes currently referenced by the tag. Evidence must be subject-bound to today’s exact digest. The correct response is to generate or locate evidence for the candidate digest, not to accept evidence by tag/name similarity.

## 11. Explain how a writable container layer differs from an image layer.

An image layer is an immutable, content-addressed changeset in the release graph. A container writable layer is runtime-instance state placed above the image’s read-only snapshot. It is not part of the approved image and usually disappears with the container. Important data must not rely on it for durability.

## 12. Design a proof that a reconstructed rootfs matches the manifest and configuration rather than merely “looks correct.”

Verify every descriptor’s digest/size/media type, decompress each layer and compare its DiffID with the configuration, apply layers in declared order with correct whiteout semantics into an empty controlled directory, and compute a normalized inventory or tree hash of the result. Then compare required files, modes, ownership, and executable bytes with the release contract.
