# Production-claims boundary

Atlas Data Plane 1.0 is a release-oriented educational reference, not an operated production storage platform.

## What the executed release proves

Dependency-light proofs establish:

- exact Course 5 handoff integrity;
- reader-book structure and educational depth;
- claim binding, topology, and scheduler reasoning;
- idempotent CSI lifecycle semantics;
- StatefulSet identity and durable fencing invariants;
- content-addressed backup inventory;
- atomic no-clobber publication in the local filesystem lane;
- symlink and non-empty restore rejection;
- snapshot consistency labelling;
- empty-destination restore and digest verification;
- migration ordering, release classification, and Course 7 handoff integrity.

## What it does not prove

These local proofs do not establish the behavior of a real Kubernetes API server, scheduler, kubelet, CSI sidecars, CSI driver, storage array, cloud volume service, snapshot controller, database engine, object store, KMS, multi-zone system, or operated recovery organization.

Those claims require the corresponding native cluster, backend, cloud, representative-scale, or operated evidence. The optional lanes fail explicitly when their dependencies are absent. The course never treats API presence, `Bound`, `Mounted`, `Ready`, snapshot readiness, or backup-job completion as proof of application consistency or recoverability.
