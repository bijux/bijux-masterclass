# Final Checkpoint — Atlas Cloud Foundation 1.0

## Required evidence

- [ ] Course 1 handoff verifies byte-for-byte;
- [ ] OpenTofu, provider, module, and dependency-lock identities are recorded or explicitly classified as not executed;
- [ ] state backend, locking, encryption, versioning, and recovery are defined;
- [ ] account, network, identity, compute, edge, and data ownership are explicit;
- [ ] accepted plan is bound to source, target, state, policy, approval, and expiry;
- [ ] non-compensable policy failures block release;
- [ ] cost, quota, replacement, and cleanup assumptions are recorded;
- [ ] request-path, host-replacement, backup, and restore proofs pass or remain explicitly not executed;
- [ ] partial-apply and state-recovery runbooks are usable;
- [ ] Course 3 handoff is complete, exact, and manifested;
- [ ] all sandbox resources are destroyed or retained under an owned lease;
- [ ] final claims distinguish dependency-light, OpenTofu-native, sandbox-cloud, and organizational evidence.

## Decision defense

Defend Atlas Cloud Foundation as a change system, not a diagram. Explain state boundaries, authority boundaries, packet paths, replacement behavior, data recovery, policy gates, cost exposure, and the precise limitations of the single-instance reference workload. Every claim must point to an artifact or be labelled unexecuted.

## Progression gate

Course completion requires the manifested dossier, final defense, clean-checkout proof, and exact Course 3 handoff. A repository full of HCL, an applied stack without recovery evidence, or a passing policy report without data-plane verification does not pass.
