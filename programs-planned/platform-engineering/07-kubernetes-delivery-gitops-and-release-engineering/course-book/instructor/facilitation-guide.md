# Instructor facilitation guide

Ask for the earliest failed transition and the owner before discussing commands. Require learners to distinguish source, render, live, health, journey, and data facts in every review.

Do not rescue a lab by revealing the planted defect. Ask which evidence is absent, which shortcut looks attractive, and which Course 6 guarantee would be weakened. Encourage one primary native lane and comparative reasoning rather than duplicated tool operation.

## Extended reader notes

Use questions that force causal ordering: “What was the earliest fact that became false?”, “Which actor owned that transition?”, “What observation would distinguish source failure from empty desired state?”, and “Does this recovery change data authority?” Avoid teaching command sequences before the learner has a model.

During native labs, require exported objects and evidence files rather than screenshots. During comparative-controller work, stop learners from duplicating setup for its own sake; ask them to map common invariants. Preserve productive uncertainty: a `not-executed` result is valid when the environment is unavailable, provided the learner explains what remains unproven.
