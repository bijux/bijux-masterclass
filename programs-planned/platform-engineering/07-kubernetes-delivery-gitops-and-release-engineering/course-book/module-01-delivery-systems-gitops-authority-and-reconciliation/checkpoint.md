# Checkpoint — Delivery systems and GitOps authority

## Required evidence

- A desired-state authority map.
- A release status with separate source, render, sync, health, journey, and data fields.
- Drift evidence for four distinct classes.
- A protected-resource prune rejection.

## Decision defense

- Explain why GitOps is a control model rather than a repository layout.
- Defend the CI/CD authority separation.
- Explain the break-glass return path.

## Progression gate

Advance only when the learner can name the owner and evidence boundary of every transition from source to running state.
