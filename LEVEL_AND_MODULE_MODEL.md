# Level and Module Model

## Fixed geometry

Each program has ten blocks of ten modules:

| Level | Blocks | Modules | Calibration |
|---|---:|---:|---|
| Level I | 1–5 | 001–050 | rigorous undergraduate core |
| Level II | 6–10 | 051–100 | graduate and professional depth |

A ten-module block is a coherent subject sequence. It is not automatically equal to university credit, but its conceptual density should be comparable to a serious university subject.

## Workload rule

The expected chapter scope stays within a narrow band.

Later modules become harder through:

- fewer hints;
- more interacting constraints;
- stronger proof or evidence requirements;
- deeper comparison;
- more realistic failure conditions;
- less obvious design choices.

They do not become harder by becoming ten times longer.

## Progression rule

A valid sequence follows this shape:

```text
foundational model
→ canonical mechanism
→ implementation consequences
→ alternatives
→ failure and limits
→ professional judgment
```

It must not follow this shape:

```text
definitions
→ more definitions
→ tool tutorial
→ tool tutorial
→ giant project
```

## Level-I completion

A learner completing Modules 001–050 should be able to:

- explain the field's core models;
- use its central vocabulary precisely;
- implement or inspect canonical mechanisms;
- solve standard nontrivial problems;
- recognize common failures;
- connect the field to adjacent programs.

## Level-II completion

A learner completing Modules 051–100 should additionally be able to:

- compare sophisticated alternatives;
- diagnose difficult behavior;
- reason about scale, concurrency, security, and failure where relevant;
- read advanced literature and specifications;
- defend decisions under technical review;
- teach the domain from first principles.

## No hidden projects

Projects after Module 050 or 100 may be defined later as separate artifacts. They are not modules and are not part of this blueprint.
